RANCHI RIDE — TRACKING & BACKEND SETUP

The refreshed website is a static GitHub Pages front-end. A static site cannot securely store bookings, authenticate drivers, dispatch jobs or publish live GPS updates across devices by itself.

To activate production operations:
1. Create a dedicated Supabase project.
2. Review and run the supplied supabase-setup.sql only after adapting it for production.
3. Add strict row-level security and authentication for customers, admins and drivers.
4. Add secure server-side booking creation, driver assignment and ride-status transitions.
5. Have an authenticated driver explicitly start GPS sharing for an assigned trip.
6. Have the customer tracking page subscribe to authorized location/status updates.
7. Stop GPS sharing when the trip ends; protect personal and location data.

Never place a Supabase service-role key, database password or other secret in public HTML/JavaScript. The admin and driver pages included here are styled interface starters only. The tracking page is not live until the backend is connected.

Map services in the earlier project use public OpenStreetMap/Nominatim/OSRM endpoints. They are not guaranteed for commercial-scale use; follow each provider's usage policy or choose a managed commercial provider.
